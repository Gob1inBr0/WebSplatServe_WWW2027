# 算法自动安装 — 详细设计实现计划

> 目标：把"新算法从零到可训练"的全过程（找仓库→下载→环境装配→冒烟验证→注册到控制台）自动化，用户在页面上点一次"安装"，十分钟后直接选数据集开训。
> 本文是详细设计与实现计划，按本文实施即可。

---

## 1. 目标体验（验收标准）

用户在控制台"算法管理"页：

1. 看到官方目录（25 个适配器声明的算法）中每个算法的安装状态：`未安装 / 安装中(步骤进度) / 就绪 / 失败(原因)`
2. 点"一键安装"→ 后台自动：克隆仓库 → 建 venv → 编译 CUDA 子模块 → 应用已知坑补丁 → 入口冒烟 → 生成启动包装器 → 自动创建连接档案
3. 全程实时显示步骤进度和日志，失败停在哪一步、原因是什么、红字可见，可"重试"
4. 成功后训练页算法下拉列表即时出现该算法，选数据集即可开训

验收：在一台全新的 LYH（只有 SHARC torch 环境）上，从页面安装一个未装过的算法（如 taming-3dgs 之外的新仓库），全程无 SSH、无命令行，最终能提交 30k 训练并出 PSNR。

## 2. 总体架构

三部分，全部复用现有基础设施：

```
控制台（算法管理页）
   │ POST /api/algorithms/install
   ▼
平台 JOBS 注册表（type=env_setup 的任务，复用训练任务的
   tmux 启动 / 日志流 / 监控线程 / 自动重试 / 失败原因捕获 / 持久化）
   │ 在服务器 tmux 里执行
   ▼
装配脚本（algs-setup，参数化生成）
   克隆 → venv → 编译子模块 → 补丁规则库 → 冒烟 → 生成包装器
   │ 每步写 status.json（与训练同格式）
   ▼
结果：注册表 registry.json（服务器）+ 控制台档案自动创建
```

**核心决策：装配任务 = 一种特殊的平台任务**，不新造后台系统。训练的 tmux 启动、日志轮询、失败原因提取、自动重试全部免费复用。

## 3. 数据模型

### 3.1 服务器端装配注册表 `/home/T0ng/algs/registry.json`

```json
{
  "algorithms": {
    "taming-3dgs": {
      "repo_dir": "/home/T0ng/algs/taming-3dgs-main",
      "venv": "/home/T0ng/venvs/taming-3dgs-main",
      "wrapper": "/home/T0ng/bin/py-taming-3dgs-main",
      "entry": "train.py",
      "status": "ready",
      "installed_at": "…"
    }
  }
}
```

### 3.2 平台任务记录（type=env_setup）

复用现有 JOBS 结构，新增字段：
- `job_type: "env_setup"`
- `setup_steps`: [{name, status, log}] 步骤级进度
- `setup_result`: {wrapper, entry, repo_dir} 成功后写入
- 复用：status/failed/failure_reason/自动重试/日志流 全部现有机制

### 3.3 补丁规则库 `web/config/algs_patch_rules.json`

```json
[
  {
    "id": "cfloat-cuda12",
    "when": {"file_glob": "**/*.cu", "contains": "FLT_MAX", "not_contains": "#include <cfloat>"},
    "then": {"action": "insert_after_first_include", "line": "#include <cfloat>"},
    "note": "CUDA 12.8 不再传递 FLT_MAX"
  },
  {
    "id": "np-cast-numpy2",
    "when": {"file_glob": "**/*.py", "contains_regex": "np\\.cast\\["},
    "then": {"action": "sed_regex", "find": "np\\.cast\\[(np\\.[a-z0-9]+)\\]", "replace": "np.asarray(..., dtype=\\1) 系列规则", "note": "逐模式映射"},
    "note": "numpy 2.0 移除 np.cast"
  },
  {
    "id": "future-annotations",
    "when": {"file_glob": "**/train.py", "contains_regex": ": (Scene|GaussianModel)\\b", "not_contains": "from __future__ import annotations"},
    "then": {"action": "insert_after_docstring", "line": "from __future__ import annotations"},
    "note": "旧 3DGS 系代码注解前向引用崩溃"
  },
  {
    "id": "torch-load-weights-only",
    "when": {"error_signature": "Unsupported global: GLOBAL numpy", "file_glob": "**/*.py"},
    "then": {"action": "sed", "find": "torch.load(checkpoint)", "replace": "torch.load(checkpoint, weights_only=False)"},
    "note": "torch 2.6+ 默认 weights_only=True"
  }
]
```

### 3.4 自愈错误签名表 `web/config/algs_fix_signatures.json`

装配/训练失败时按日志尾的错误签名自动应用已知修复并重试一次（复用自动重试机制，重试前先跑修复动作）：

| 日志错误签名 | 自动修复动作 |
|---|---|
| `No module named 'X'` | pip install（X→包名映射表：cv2→opencv-python-headless、yaml→pyyaml、plas、fused_ssim→克隆 fused-ssim 仓库…） |
| `FLT_MAX is undefined` | 应用 cfloat 规则 |
| `np.cast was removed` | 应用 np-cast 规则 |
| `name 'Scene' is not defined` | 插入 future annotations |
| `Unsupported global: GLOBAL numpy` | torch.load 加 weights_only=False |
| `indices should be either on cpu or on the same device` | torch.arange 加 device 参数（arange 设备规则） |
| `Address already in use` | 端口自动 +1 补丁（已全局应用） |
| `AttributeError: … has no attribute '_encoder'` | compressai rans 接口垫片（RDO 案例） |

## 4. 服务端设计

### 4.1 装配脚本生成器 `web/server/algs_manager.py`（新文件）

纯函数 + SSH 执行，职责：

```python
CATALOG_SOURCE = "web/config/algorithm_adapters.json"  # 25 个适配器=目录来源

def build_catalog(installed_registry) -> list
    # 合并：适配器声明的算法 ∪ 服务器已发现的仓库，附安装状态

def generate_setup_script(name, repo_url|repo_dir, entry) -> str
    # 返回 bash 脚本文本（写到任务目录，tmux 执行）：
    # step clone:   git clone --depth 1 <url> /home/T0ng/algs/<name>  （已有则跳过）
    # step venv:    SHARC -m venv --system-site-packages /home/T0ng/venvs/<name>
    # step compile: 逐个 submodules/*/setup.py pip install --no-build-isolation
    #               每个失败→查补丁规则库→应用→重试一次
    # step patch:   应用全部补丁规则库到仓库源码
    # step deps:    适配器 python_modules 里缺的 pip 包（cv2→headless 映射）
    # step smoke:   entry -h → 失败→查自愈签名表→修→重试（最多 3 轮）
    # step wrapper: 生成 /home/T0ng/bin/py-<name>（动态选卡版）
    # step result:  写 status.json {status: ready|failed, failure_reason, steps[]}

def relaunch_setup(...)  # 自动重试复用
def uninstall(name)      # 删 venv + 仓库（可选保留），从注册表移除
```

### 4.2 状态机

```
queued → cloning → venv → compiling → patching → deps → smoking → ready
                └────────任一步失败────────→ failed(reason, step)
failed --自动重试(重跑失败步骤)--> 原步骤
```

### 4.3 与训练任务的资源协调

- 装配任务是 CPU/IO 型，训练是 GPU 型，天然互补；装配并发限 2（信号量）
- 提交训练时校验：目标算法 `status == ready`，否则 400 + 原因（"算法未安装/装配中"）

## 5. API 设计（全部 token 鉴权，复用现有 _security_gate）

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/algorithms/catalog` | 目录+状态+缺失原因汇总 |
| POST | `/api/algorithms/install` | {name, repo_url?, entry?} → 202 + job_id（env_setup 任务） |
| POST | `/api/algorithms/{name}/retry` | 重跑失败步骤 |
| DELETE | `/api/algorithms/{name}` | 卸载（删 venv，保留仓库） |
| GET | `/api/algorithms/install/{job_id}` | 装配进度+日志（也可走现有 jobs 流） |

## 8. 安全与边界

- 全部接口 token 鉴权（复用 _security_gate）
- git URL 限定 https；克隆加 --depth 1 与超时；装配并发限 2
- 磁盘护栏：装配前检查可用空间 ≥3GB，不足直接拒绝并提示清理
- 卸载只删 venv 与注册表条目，仓库目录默认保留（防误删数据）
- 平台是本机单用户工具 + token 鉴权，自定义 URL 的供应链风险由用户自担（页面上提示）

与设计的差异（实现时的决定）：

- **API 形状**：卸载用 `POST /api/algorithms/{name}/uninstall`（沿用本仓库 POST-delete 约定，而非设计表的 DELETE）；catalog 同时提供 GET（本地缓存视图，无需凭据）与 POST（带连接凭据实时扫描服务器）两种形式。
- **目录布局参数化**：注册表/仓库/venv 路径由 profile 的 `workspace_root` 推导（`<data_root>/algs|venvs|bin`），不写死 `/home/T0ng/...`，天然支持多服务器。
- **自愈位置**：签名表驱动的"先修复再重试"发生在装配脚本内部（冒烟最多 3 轮、编译失败先补丁再重试一次），外层不再做基于日志的自动重跑；显式"重试"通过步骤级 `.done` 标记跳过已成功步骤，从失败步骤继续。
- **训练提交拦截**：只拦截"装配中"的算法（400 + 任务号）；装配失败但手动修好的仍允许提交（以适配器/注册表状态为准），避免误伤手工配置的服务器。
- **安装成功后的档案**：等价实现为适配器 override 回写（repo_path/default_cwd 指向远程仓库绝对路径 + env_setup 元数据）；自定义仓库安装会生成带 vanilla 训练模板的完整新适配器。wizard 提交时检测到绝对路径即覆盖 `remote.repo_path`，训练直接落到新装仓库。

已知限制（首版）：

- 服务器重启时进行中的装配任务会标记为 detached，需在算法管理页重试（步骤标记保证从断点继续，已成功的 clone/venv/编译不重做）。
- 自定义仓库训练模板为 vanilla（`train.py -s/-m/--eval`），参数特殊的仓库需手动补适配器模板。
- arange-device 规则只能推断 `len(x)` / `x.shape[n]` 两种容器的 device，裸常量 arange 仍需手改。
