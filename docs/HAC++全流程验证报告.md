## 过程中发现并解决的问题（按时间序）

1. **向导"下一步"死锁**（已修复，提交 5ca4cda）：按钮解锁条件要求上传回执，而上传只能由该按钮触发。改为"已选图 + 有名字"即解锁。
2. **上传 413**（已修复，提交 b145480）：此前安全加固的全局 1 MB 请求体上限误伤 base64 图片上传。改为按端点限额：/api/stream-frame 32 MB，其余 1 MB。
3. **远程预检 400：缺 xvfb-run**：自动 COLMAP 工作流需要虚拟显示。服务器装 `colmap + xvfb` 后通过。注：用户此前遇到的"卡在远程环境检查"即是此错误——报错提示消失后页面停在等待态，这个 UI 小问题待改进（错误应常驻显示）。
4. **HAC++ 启动即崩（版本守卫）**：仓库自带的 torch 2.2/cu121 硬检查拒绝当前环境。已在服务器放宽为警告（见前置准备 3）。
5. **训练 OOM（51 GB 分配请求）**：两个因素叠加——任务默认跑在 GPU 0（被占卡，仅剩 1 GB），且体素 0.001 对该场景生成海量锚点。原计划用档案"激活命令"写 `export CUDA_VISIBLE_DEVICES=1`，但激活命令有安全校验（只允许纯 conda/venv 激活命令，拒绝 export）。改用**GPU 包装解释器**方案：服务器上建 `/home/T0ng/bin/python-gpu1`（内部设 CUDA_VISIBLE_DEVICES=1 后转发真实 python），档案 Python 字段指向它——完全在 UI 配置层解决，预检合规通过。配合体素 0.01 后 29.7 迭代/秒、显存 1.2 GB，一次跑完。
6. **"复用服务器数据"列表为空**（设计缺陷，未修）：数据集扫描按算法族子目录查找，而向导第一步尚未选算法，族为空时永远扫不到。本次绕过（重走上传路径），建议后续把扫描改为族无关或允许手填路径。

## 这个功能的使用说明（给下次使用的人）

这套控制台把"3DGS 训练"压缩成四步，全程浏览器操作、无需登录 GPU 服务器敲命令：

1. **连服务器（一次）**：设置 → 新建档案 → 三选一：粘贴 ssh 命令 / 从 ~/.ssh/config 导入 / 手填。填仓库路径（算法仓库在服务器上的位置）和 Python（环境解释器绝对路径）；数据目录自动推导，可用"探测数据盘"落到真实大盘。密钥认证填本机私钥路径即可，无需密码。
2. **新建训练**：上传照片（8 张起，上百张亦可）或复用服务器已有数据集；无稀疏模型时勾选自动 COLMAP，服务器自动完成特征提取→匹配→稀疏重建。
3. **选算法与规模**：下拉选算法（3DGS、HAC++ 等 20 种适配器），档位三选：快速预览 3k（约 10 分钟）/ 标准 30k（论文级）/ 自定义（任意迭代数与超参）。
4. **提交与监控**：自动远程预检（SSH、仓库、运行时、COLMAP、磁盘逐项检查）→ 命令预览可人工核对 → 启动。任务在服务器 tmux 会话里跑，关浏览器不影响；运行页看状态、日志、PSNR/SSIM 指标，完成后结果自动回传本地。

两个实用细节：训练跑在空闲 GPU 上需要时，用档案"激活命令"写 `export CUDA_VISIBLE_DEVICES=<n>`；快速验证流程用 5k 迭代 + 体素 0.01，几分钟出结果。
